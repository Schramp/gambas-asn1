# xval_sweep targets — one per line: "<schema.asn1 path relative to asn1cpp/>  <PDU type name>  [skip-asn1c-reason...]"
# '#'-prefixed and blank lines ignored. Paths are relative to asn1cpp/'s own
# root (this tool lives inside asn1cpp/, no umbrella-repo path assumptions).
#
# A target qualifies when: (a) the schema compiles cleanly under asn1cpp
# for both --target=cpp and --target=rust, (b) the named type is a real
# top-level PDU/message type — SEQUENCE/CHOICE/SET, ENUMERATED, or a
# named SEQUENCE OF/SET OF (the C++ leg auto-detects whether that
# compiles to a real wrapper class or a bare `using` alias and picks
# the right descriptor reference, discover_cpp_descriptor_ref() —
# xval_sweep.py; a bare scalar alias to a builtin, e.g. `X ::= INTEGER`
# with no SEQUENCE OF/SET OF involved, still doesn't qualify, no
# descriptor at all to register), and (c) the type has no unresolved
# cross-file import outside this line's schema file
# (multi-file schemas aren't supported by this first pass — see gambas-
# asn1#434's own "Not included here" note). PDU type names may contain
# hyphens or other characters that need escaping in the generated C++/
# Rust identifier — xval_sweep.py's discover_ident() finds the real
# generated identifier by content, not by guessing the escaping rule.
#
# Optional 3rd+ column: a known, already-filed asn1c divergence for this
# specific target (#440's asn1c leg) — C++/Rust legs still run and gate
# pass/fail as always, asn1c leg is skipped rather than failing on a gap
# tracked elsewhere.
#
# Seeded with 3 single-file test schemas (broad type coverage, tag
# coverage, CHOICE coverage) plus 10 more probed from asn1c's own mirrored
# test suite (tests/tests-asn1c-compiler/*-OK.asn1) and confirmed to
# build + round-trip end-to-end. Full population of the rest of the test
# corpus (~140 more -OK.asn1 files, plus the real ETSI/3GPP schemas) is a
# follow-up pass, not done here.
#
# 6 other probed candidates that parse-checked clean but failed a full
# build or round-trip were deliberately left out — real gaps, filed
# separately rather than silently excluded:
#   gambas-asn1#435 — X.681 Information Object Class field-type reference
#     (`Type.&id`) resolves to a literal, nonexistent `#include` instead
#     of the referenced type (164, 168, 172, 173)
#   gambas-asn1#436 — fixed for C++ (PR #449) and Rust (PR #453, boxed
#     self-referential alternative — rustc otherwise rejects the plain
#     enum variant as an infinite-size recursive type). Now an active
#     target below (no skip-asn1c needed — this schema's RecChoice has no
#     own [n], so gambas-asn1#448's EXPLICIT/IMPLICIT bug never applied
#     to it in the first place).
#   gambas-asn1#437 — deeply nested anonymous CHOICE-in-CHOICE promoted
#     synthetic type has no Rust Asn1Value impl (201) — fixed, PR #451.
#   gambas-asn1#438 — fixed: ENCODING-CONTROL XER BASE64 instructions
#     (both legacy `TypeName OCTET STRING ::= base64` and standard
#     `BASE64 TypeName` forms) were parsed and silently discarded; now
#     threaded through to TypeDescriptor::xer_encoding (C++, already had
#     runtime support) and a new base64_encode/decode pair in RustBackend/
#     rust-runtime/ber (Rust had none at all). 180/183/210 (SEQUENCE-OF/
#     inline-member cases) still unconfirmed — not yet re-probed.
#   gambas-asn1#443 — fixed: the third ENCODING-CONTROL instruction form,
#     `TypeName OCTET STRING ::= utf8` (raw UTF-8 text, X.680 §11.15
#     control-character/entity escaping), threaded through the same
#     xer_encoding path #438 wired up, with new C++ (XerCodec.cpp) and
#     Rust (octet_string.rs) runtime encode/decode.
#   gambas-asn1#441 — fixed: top-level (non-member) CHOICE XER output now
#     gets the X.693 §8.3.1 document-element wrapper asn1c always emits,
#     in both C++ (XerCodec.cpp) and Rust (choice.rs).
